How DraconDex works

DraconDex has one idea at its centre: a Nexus holds a tree, and every node in that tree picks what kind of thing it is. Learn that and the rest follows. This page covers the tree, the fifteen kinds a node can be, and the systems that cut across all of them.

Getting started

Three steps to a working vault

  1. Install and open the app. On first run it asks for a language and a theme — both changeable later in Settings.
  2. Create a Nexus. A Nexus is one world, saved as one .ddx file wherever you choose to put it. One novel, one Nexus is the usual arrangement.
  3. Build the tree. Add a node, give it a name, pick its kind. Nodes nest as deep as you like — there is no fixed two-level structure to work around.

Nothing leaves your machine. There is no account and no server; the cloud features further down are opt-in and use storage you own.

The core idea

A Nexus holds one tree

Every node is a module. A module has a name, an icon, a colour, a description written in markdown, and a kind that decides what opening it actually shows you. A node can hold other nodes, to any depth.

Pin what you use

Top-level modules can be pinned to the rail down the side of the window, so the things you open every day are one click away.

Give it a handle

Any module can take a short @handle, unique within the vault. Handles are what the quick switcher searches, so a long name never gets in the way of reaching it.

Nothing is lost

Modules keep a version history, and the whole app has session-wide undo. Tags and colours cut across the tree when the hierarchy is not the grouping you want.

Reference

The fifteen module kinds

A kind is chosen when the module is created. The name in grey underneath is what the app labels it in the interface — the kind name is what the documentation calls it.

Kind What it is When to reach for it
Collector
Folder		 An empty folder. It groups children and has nothing to open itself — click it to expand or collapse. Use it to shape the tree: a “Characters” collector holding one module per character.
Manager
Project		 A container that shows a module's children as Cards, List, Table or Graph. The default hub for any module that has children. Switch view from the pane head; the choice is remembered per module.
Inspector
Detail		 One long-form note, bound to the module's own description field. The simplest way to write about a single thing. Supports markdown and [[wikilinks]].
Classifier
Category		 Categories, objects and fields in one table — the system the old Director module used. Separates object, character and element types. Each element gets a detail page with levels, conditions and dates.
Locator
Map		 A canvas map where an area is a polygon you draw. Drop a map image, outline regions, and link each one to a module.
Chronicler
Timeline		 Events on an invented calendar. Creates one timeline when you make the module. You can define your own units of time — see Custom calendars below.
Wanderer
TimeMap		 Event pins on a Locator map, tied to Chronicler time. Answers “where was this, and when” — scrub time and watch the pins move.
Narrator
Story		 A dialogue graph: nodes and edges, a route board. One dialogue is an ordered list with two kinds of row — a spoken line, or a branching choice.
Author
Book		 Chapters down the left, a markdown editor on the right. Outline mode for structure, Reading mode for prose.
Scribe
Chat		 Chat-style notes attached to one module — bubbles with timestamps. For thinking out loud against a specific thing, rather than a formal note.
Drafter
Doc		 A blank markdown page. Uses the module's own description field, so there is nothing else to manage.
Viewer
Analys		 A read-only lens over a saved filter, as Table, Cards or Board. Build the filter once, then look at it from three angles without duplicating anything.
Connector
Relation		 A relationship graph over a saved filter — nodes are items, edges are relations and wikilinks. Shows how the things you wrote about actually connect.
Sketcher
Drawing		 A freehand canvas: pen, eraser, multiple pages, PNG export. For the map sketch or the character doodle that does not need to be a real map.
Designer
Graph		 A free-form diagram — shapes, edges, labels, dragged into place. Thirteen shapes, with a picker behind the “more” button.
Across the app

Systems every module shares

Nexus files

Each Nexus is its own .ddx file on your disk, plus one app.ddx holding settings and the vault list. Move a .ddx to another machine and it opens there.

In depth: docs/VAULTS.md

Wikilinks and backlinks

Type [[a module name]] anywhere markdown is accepted. The link resolves as you type, and the thing you linked to gains a backlink pointing home.

In depth: docs/SYSTEMS.md

Custom calendars

A Chronicler timeline does not have to use Earth months. Define your own units — how many days in a week, how many weeks in a month — and the graphs, the time strip and the calendar view all follow.

In depth: docs/SYSTEMS.md

Themes and language packs

Beyond the 32 themes and 18 languages built in, the app can install more from the package repository: a theme, a translation, or a view preset. Settings → Plugins → Packages.

In depth: DraconDex-PKG

Plugins

Paste a git repository link and DraconDex shows you what the plugin declares before anything is written. Each one gets its own tables and runs in a separate sandboxed window.

In depth: docs/PLUGINS.md

Cloud Sync

Off by default and opt-in per install. You bring your own Supabase project, so the data never passes through anyone else's server.

In depth: docs/SYNC.md

DDX Transfer

Send a whole Nexus to another device with a code and a PIN — no account, no setup. The file is encrypted before it leaves, and the copy in the middle is deleted the moment it arrives, or after 30 minutes if nobody comes for it. It is a hand-off, not a backup and not a sync.

In depth: docs/TRANSFER.md

Google Drive backup

The one connected cloud feature: back a vault up to your own Drive and restore it later.

In depth: docs/DRIVE.md

Update checks

DraconDex tells you when a newer version exists and links to it. It does not download or install anything by itself.

In depth: docs/UPDATE.md
